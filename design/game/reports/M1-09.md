# M1-09: Specify interface flows and accessible states — evidence report

Date: 2026-10-17

## Scope

Produced `design/game/ui-spec.md`: a compact screen/state map and component inventory for the six screens named in `design/game/interface.md` (Account Selector, Company, Expedition, Inventory, Boss, Arena), mapping every action to a real `contracts.md` endpoint and every display string to a `narrative/copy.md` key (plus a small, itemized set of copy additions in the same style for strings `interface.md` requires but `copy.md` doesn't yet name). No new game system, numeric rule, or mandatory art dependency was introduced; all visuals are specified as text/CSS using the existing palette direction. Planning only — no code was written (M1-10 implements against this spec).

## Acceptance checks

1. **Every screen/action maps to real contract endpoints and copy keys, including result/retry/conflict states.**
   - Check: for each of the 6 screens, enumerated every mutating/reading action against `contracts.md`'s endpoint list and cross-checked every player-facing string against an existing `copy.md` key or an explicitly itemized addition.
   - Result: **Pass.** Each screen section in `ui-spec.md` lists its exact endpoint(s) (e.g. Expedition → `POST /expedition/start|settle|stop`, Arena → `POST /arena/publish|challenge` + `GET /arena/snapshots[/:id]`) and cites copy keys by name (e.g. `boss.reward.already_claimed.title`). Result/retry/conflict handling is specified once as shared components (`ActionRejectedToast`, `ServerErrorToast`, `ConflictRefetchToast`, `OfflineBanner`) in the Global conventions section and referenced per screen rather than restated six times, to keep the spec compact per the task's "compact" requirement. **Review-fix correction:** the Expedition screen's error list previously claimed `active_expedition` was unreachable from all three of start/settle/stop; `contracts.md:94` shows `/expedition/start` does return `active_expedition` (one already running) while settle/stop (`contracts.md:100`) do not. `ui-spec.md` now gives `/expedition/start`'s `active_expedition` its own handler.

2. **Keyboard/focus behavior, desktop/narrow layout and disabled-action explanations are specified.**
   - Check: confirmed a global keyboard/focus baseline exists and that every screen section has its own Keyboard and Layout subsection; confirmed every disabled control in the spec cites a specific copy key explaining why.
   - Result: **Pass.** Global conventions fix focus-visible, tab order, reduced-motion, and the 1280×720/390px breakpoints from `interface.md`. Each screen adds screen-specific keyboard notes (e.g. up/down reorder buttons instead of drag-and-drop on Company, for keyboard parity). Disabled-action copy keys were added where `copy.md` had none (`disabled.spec_locked_level`, `disabled.spec_locked_expedition`, `disabled.equip_locked_expedition`, `disabled.party_incomplete`, `disabled.item_wrong_slot`), each tied to a specific frozen rule from `contracts.md` (level-3 gate, loadout freeze during active expedition, slot mismatch).

3. **Gear comparison, specialization choice, credited/discarded offline time and snapshot version are understandable without developer jargon.**
   - Check: reviewed each of the four flows for plain-language framing.
   - Result: **Pass.** Gear comparison uses a "Now → After" plain-language delta table (e.g. "Attack +3"), not raw stat codes. Specialization choice shows the two spec names/descriptions from `copy.md` directly, gated by plain text ("Reach level 3…") rather than exposing `specializationId`. Offline time reuses `expedition.offline_cap.title`/`.body` verbatim and only surfaces discarded time when nonzero. Snapshot version is rendered as "Published Oct 12 under ruleset v1" rather than exposing `rulesVersion`/`schemaVersion` as raw fields.

4. **No new game system or mandatory art dependency is introduced.**
   - Check: reviewed every component for a hidden new rule or required image/icon asset.
   - Result: **Pass.** All stat/reward/combat numbers displayed are read from already-frozen `contracts.md` response shapes or `content.md`-derived item stats (via copy/content already fixed in M1-02/M1-03), never recomputed or invented in the UI layer. Portrait/icon slots are explicitly not used; class/item/enemy identification is by text label throughout, consistent with `interface.md`'s "text or initials until optional original assets exist."

## Unresolved issues (carried into `ui-spec.md`'s "Unresolved issues for M1-10" section)

1. Expedition settle/stop responses in `contracts.md` have no `reportId`/`events` field (only aggregate rewards), unlike boss/arena's full `BattleReport`. Whether expedition cycles have a retrievable per-cycle combat log is not fixed by any read input; the spec's `CombatLogPanel` is written to degrade to aggregate-only if no such log exists. Not a blocker — this is a display-detail question for M1-10, not a missing endpoint the UI depends on.
2. No `copy.md` key exists for any `report.result` outcome label (win/loss/draw) — not a boss-loss-specific message, and not an arena draw message. `combat.md:103-104` defines arena's **draw** outcome (round-100 timeout, or the simultaneous-defeat edge case) as distinct from PvE/boss's **loss** on the same conditions; `BattleResultPanel` must branch `report.result` three ways, not two, but no copy exists for any of the three branches beyond plain structural labels. The result panel can render the server's structured result without new copy; warmer lines for all three outcomes are optional polish, not required for correctness.
3. `contracts.md` does not specify different arena-challenge behavior when a snapshot's `rulesVersion` differs from the challenger's current version. The spec displays the version plainly but does not add a blocking confirmation, since no rule requires one.

None of these block M1-10: each is either a graceful-degradation note or an optional-copy gap, not a missing contract the UI depends on.
