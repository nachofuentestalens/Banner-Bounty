## Context

The owner's M1 playtest verdict ("way too basic... extremely boring... I need to be able to see what
each unit is doing, how much HP they have left") drives M2 (`design/studio/milestones/M2.md`). This
task specifies the combat/class/skill/formation core of that depth milestone: exact, implementable
rules and bounded content, building on M1's frozen `combat.md`/`content.md` and the already-landed
combat-replay baseline (`reports/engineering/M2-21.md`).

## What changed

- **`design/game/classes.md`** (new) — 6 base classes (Vanguard=Tank, Cleric=Healer, Ranger/Rogue=
  Physical damage, Arcanist=Magic damage, Herald=Support; Vanguard/Ranger/Arcanist keep M1 stats
  unchanged), the dual-class stat-layering formula and 6 named synergy pairs, the 2-active/2-passive
  skill-loadout system with automatic action-priority execution, a full 5-skill kit per class (30
  skills total, exact numbers/cooldowns/targeting), a generalized 6-entry status-effect table
  (Burn/Weaken/Fortify/Haste/Regen/Taunt), 5-slot front/back-row formation rules, a 20-hero roster cap
  with a gold-priced recruitment mechanic, a migration plan from M1's `Hero`/`PartyOrder` shape, and 5
  worked examples.
- **`design/game/combat.md`** (amended) — section 8 appended ("Combat v2, M2-22 addition"): round
  structure v2 (dynamic SPD recompute, cooldown/duration bookkeeping), row-protection and taunt-override
  targeting (extends 3.1), a deterministic crit/dodge RNG pipeline that finally consumes `rngSeed`
  (reserved-but-unused since M1 section 7), healing/buff/AoE generalization, the reference PRNG and
  exact roll-consumption order, and an additive `BattleEvent` extension (`skillId`, `crit`, `dodged`,
  `statusApplied`, `statusExpired`, `death`) built directly on the real shape in
  `packages/game/src/combat.ts`. Sections 1-7 (the M1-02 freeze) are untouched, with a one-paragraph
  pointer added at the top.
- **`design/game/content.md`** (amended) — section 5 appended: the class/spec table superseded (points
  to `classes.md`), three new `classId`s added, the Old Road's 3 enemies and the Tollkeeper reworked to
  use cooldown-gated skills, a debuff, HP-seeking AI variety, and (Tollkeeper only) row-protection-
  ignoring + taunt-respecting targeting — a concrete reference implementation of combat v2 on existing
  content. Authoritative roster-cap/recruit-cost numbers are placed here (content.md already owns
  content-table numbers); section 5.5 explicitly scopes out designing *additional* areas/dungeons.

No code, contract, or test files were touched — this is a design-document-only task.

## Decisions made (routine, reversible, recorded per `AGENTS.md` rule 4)

1. **Threat modeled as binary per-side Taunt, not a numeric score** — keeps targeting fully
   deterministic/bounded while still satisfying M2.md acceptance check 8.
2. **Vanguard/Ranger/Arcanist keep M1 stat tables and `classId`s unchanged**; only their action kits
   are reworked (specializations → skills). Minimizes migration risk and blast radius.
3. **Level cap stays 1-10** (M1 baseline) — raising it is Economy Designer/M2-28 scope, not reopened.
4. **Party minimum relaxed to 1-5** (from M1's exact-3) since M2.md doesn't require always-fielding 5
   and a hard minimum would make a thin roster unplayable.
5. **Recruitment is gold-priced, class-chosen, no RNG identity roll** — preserves the no-pay-to-win,
   player-agency posture already established in `vision.md`/`first-playable.md`; RNG is scoped to
   combat crit/dodge only. Roster cap 20, cost `150 * ownedHeroCount` gold — flagged explicitly as a
   placeholder default open for Economy Designer retuning (M2-28), not a frozen economy number.
6. **No manual/real-time player input introduced** — M2.md's "real decisions" are build decisions
   (loadout, formation, class pairing), executed automatically in battle via a fixed slot-priority rule,
   consistent with M1's existing "no player scripting" invariant and with M2.md's explicit framing
   (playback controls, not live input).
7. **Scope boundary: did not design new areas/dungeons.** M2.md scope item 6 ("several expedition
   areas... multi-floor dungeons") has no explicit owner in the M2 task table beyond engine
   implementation (M2-26). This task's content.md amendment is bounded to reworking the *existing* Old
   Road/Tollkeeper content as the reference implementation of combat v2; designing additional area/
   dungeon rosters is flagged as an open item below for the Producer, not undertaken here and not
   delegated via a new task (per this task's explicit instruction not to create duplicate backlog
   tasks).
8. **Did not edit `ui-spec.md`/`interface.md`.** This task's explicit deliverable list (per its actual
   instructions, not the Systems Designer role's general M1-02/M1-09 charter boilerplate) is
   `combat.md`, `content.md`, and `classes.md`. The battle-view data needs (live HP, skill used, exact
   numbers, status duration, death notice, cooldown-implied state) are described in `combat.md` 8.6 as
   "what the battle view renders," informational for M2-27, not a UI-spec rewrite — avoids conflicting
   with M2-27's ownership of the actual screen/state map.
