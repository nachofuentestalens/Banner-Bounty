## Found issues

**1. `tests/e2e/api-attacks.mjs` and `malformed-payloads.mjs` call a route that no longer exists (QA test bug, not a game defect).**
Both scripts call `PATCH /party/order` with a 3-element `order` array of hero IDs. The server only exposes `PATCH /party/formation`, taking a 5-slot nullable `slots` tuple (`apps/server/src/app.ts:157`, `PartyFormationRequestSchema` in `packages/contracts/src/index.ts:409`) — this is the M2-25 party-of-5 contract amendment superseding the M1 3-hero `order` shape these scripts were written against. Every call fails with `404 not_found`, cascading into 6 failed assertions across the two scripts (A02.4, A07.1, A07.2, A05.3 in api-attacks; 2 in malformed-payloads). I did not rewrite these call sites: fixing them correctly requires modeling the new 5-slot semantics across ~9 call sites in 4 files (`api-attacks.mjs`, `boss-arena.mjs`, `browser-ui.mjs`, `malformed-payloads.mjs`) and re-verifying each assertion's intent still holds for 5 slots, which is beyond a smoke-check pass. Flagging as a QA harness maintenance gap, not a product defect — the underlying product behavior (ownership checks, retry idempotency, concurrent-settle, mid-expedition reorder) was not actually exercised by these 6 assertions this run.

**2. `tests/e2e/combat-replay.mjs` looks for a button that was never named "Next action" (QA test bug).**
`apps/web/src/components/BattleView.tsx` has a working replay control bar (`Play`/`Pause`, `Step`, `Restart replay`, `Skip to end`, speed selector — lines 220-254). The script waits for `getByRole('button', { name: 'Next action' })`, which doesn't match any current label, and times out after 30s. Confirmed by reading source, not by inference. Combat playback itself exists in the UI; this script's selector is stale.

**3. `tests/e2e/inventory-overflow.mjs`'s seed fixture references a dropped column.**
The script inserts rows directly into `item_instances` with an `affixId` column. The current schema stores affixes as a JSON array column (`affixes`, see `apps/server/src/progression.test.ts:77-78` and `apps/server/src/repositories/itemRepository.ts`) per the M2-23 gear/rarity rework. 3 of 4 checks fail with `table item_instances has no column named affixId`, and the script crashes on teardown (`EBUSY` deleting its temp DB on Windows) after the first SQL error leaves a connection open. Needs a QA fixture update to the current schema, not a product fix.

**4. `tests/e2e/browser-ui.mjs` keyboard/UI checks fail against M2's expanded navigation (likely stale selectors, not confirmed defects).**
4 of 9 checks failed: tab order lands on a skill button ("Firebolt") before reaching "Expedition" nav; the script can't find a "Stop and Collect" or "Challenge" label (nav now includes added Dungeon/Arena/Switch Account entries per M2); and a "Move down" party-reorder button it expects no longer exists (likely replaced by the new 5-slot formation control from issue #1). I did not independently confirm whether keyboard focus order and labels are *actually* broken for a real player, versus the script simply targeting pre-M2 labels — that distinction needs a manual pass or an updated script, which is out of scope for this smoke run. The account-isolation-via-UI assertion in the same script (A02/A10: B cannot read A's report) did pass.

None of the above were fixed in this run — `tests/e2e/` was read and diagnosed but not edited, so no commit is produced by this task.
