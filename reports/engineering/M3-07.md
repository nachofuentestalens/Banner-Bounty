## Phase 2 changes and decisions (2026-11-07, this session)

- **Timing (`settlement3.ts`):** a generic pure `runSettlementWalkV3` implements
  contracts.md section 4's variable-duration settlement walk — elapsed/cap/
  discard math, cached-pending vs. credited battle semantics, the generalized
  no-op rule (a new reveal bumps revision even with nothing credited), and
  resumable multi-call catch-up under `maxBattlesPerSettlement`. It is
  parameterized over a `rollBattle(rngState) -> {roll, nextRngState}` callback
  so the module has no opinion on which content area or reward table a battle
  belongs to; a `beforeRoll(ordinal)` hook fires immediately before every new
  roll, which is where deferred skill changes apply (see next).
- **Deferred loadouts (`loadout3.ts`):** implements contracts.md section 5.
  `computeBoundaryOrdinalV3` is a direct read of `SettlementStateV3.nextOrdinal`
  — that field is already exactly "the next not-yet-rolled ordinal" by
  construction, whether or not a battle is currently cached as pending, so no
  branch was needed to distinguish the two cases contracts.md's prose
  describes. `queuePendingSkillChangeV3` validates against the frozen
  level/class pool via the existing `validateLoadoutV3` and records the
  boundary; `cancelPendingSkillChangeV3` classifies cancel/already-applied/
  not-found without fabricating a cancellation; `applyDuePendingChangesV3` is
  invoked from the walk's `beforeRoll` hook; `discardPendingOnStopV3`
  implements the stop-time discard-only-unconsumed rule.
- **Competition (`competition3.ts`):** season epoch/window arithmetic; the
  four `fixture_m3_01..04` companies built via the existing `autoFillLoadoutV3`
  at level 5 (exact class compositions from m3-systems.md section 8); seat
  filling; the double-round-robin schedule builder (12 matches: 6 pairs ×
  2 legs, pair-lexicographic ordering, A/B swap between legs, pluggable
  deterministic seed function — never `Math.random`); standings ranking
  (points desc, wins desc, entryId asc); tournament bracket seeding (1v4,
  2v3 by ascending entryId); draw/timeout advancement tiebreak (normalized
  HP -> survivor count -> seed number, matching contracts.md section 11
  exactly); and the recovery-only bye/vacancy matrix (one vacant seat -> bye,
  no report/score; two vacant -> no winner; a bye-decided final withholds
  the title).
- **M3 dungeon runner (`dungeon3.ts`):** `simulateDungeonRunV3` is the piece
  `combat3.ts` alone didn't provide — sequential floor 1..N simulation using
  `buildEnemyCombatantsV3`, stopping on the first loss or the boss floor's
  clear, full HP every floor, normalized per-hero HP-ratio output (feeds the
  tournament tiebreak shape and the tactical matrix below). Isolated from the
  legacy `dungeon.ts`/`combat2.ts` pairing, same per-rules-version separation
  `combat3.ts` already established — a future combat fix must be assessed
  against each rules version independently.
- **Tactical measurement (`scripts/simulate-v3-tactical.mjs`):** runs
  economy/m3.md section 6's protocol for pairs (a) no-new-class
  counterexample, (b) Warder-included, (c) Weaver-included (all vs. an
  equal-gear glass-cannon five, against Cinder Archive floors 1-4), and
  (e) the three races (identical level-5 3-hero class spread) against Old
  Road. **Pair (d), the 16 specialization pairs, is not run** — see Remaining.
- **Catch-up benchmark (`scripts/simulate-v3-catchup.mjs`):** benchmarks one
  real `runSettlementWalkV3` call at the full 8-hour cap using actual
  `combat3` battles, 20 repetitions, same min/median/p95/max + hardware
  report shape as the existing legacy `--mode=catchup` benchmark.
- Both package indexes (`packages/game/src/index.ts`) export every new
  module. `package.json` gained `simulate:v3-tactical`/`simulate:v3-catchup`
  script entries alongside the existing `simulate`. No Design/Leadership/QA
  document was edited; `packages/game/M3.md` gained a "Phase 2" section with
  the same content summarized here.
