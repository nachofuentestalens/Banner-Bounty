## What changed

**Serving and launch (apps/server, scripts, package.json)**
- `apps/server/src/http/staticClient.ts` (new): a dependency-free static handler registered as Fastify's
  not-found handler. API routes always win. `GET /` serves `index.html` (`no-cache`), existing files under
  dist are served with a content type, and asset caching is immutable because Vite fingerprints names.
  Anything else, including traversal attempts and non-GET requests, returns the contract's `not_found`
  envelope. Unknown API paths are never masked as a page.
- `app.ts`: new optional `webDistDir`. `config.ts`: `DEFAULT_DB_PATH` / `DEFAULT_WEB_DIST` are resolved from
  the module location, and there is a new `SERVE_WEB=0` / `WEB_DIST` option. `main.ts`: logs the save path
  and built-client status, and prints an actionable message on `EADDRINUSE` (exit 1).
- `scripts/dev.mjs`: the API child runs with `SERVE_WEB=0`, so Vite stays the only UI in dev.
- Root scripts: `start` (one-process release preview), `save:path` / `save:backup` / `save:reset`
  (`scripts/save.mjs`), and `walkthrough` (`scripts/walkthrough.mjs`). Root devDependency
  `@playwright/test@1.64.1` (exact pin; Playwright is the preselected browser tool in tech-stack.md).

**Defects fixed**
1. **Arena result vanished on any state refresh (P1 for the arena loop; latent since M1-10).**
   `SnapshotPreviewPanel`'s load effect depended on `controller`, a new object on every state update. The
   5 s poll or any refetch reloaded the preview and cleared the challenge result. Fix: read the controller
   through a ref and key the effect on `snapshotId` only.
2. **Arena challenge left a stale revision (P2).** The challenge bumps the account revision but did not
   refetch, so the next mutation on any screen got a 409 and the player had to click again (seen in
   walkthrough step 9). Fix: `await controller.refetch()` after a successful challenge.
3. **Inventory comparison showed a raw UUID (P2).** The "Now" column passed `hero.equipment[slot]` (an
   item *instance* ID) to copy lookups that need a *definition* ID. Fix: resolve the instance from inventory
   and show its name and affix.
4. **Company card copy (P3).** A level-3+ unspecialized hero showed "Reach level 3 to choose a
   specialization." It now says "Unspecialized — specialization available".
5. **Duplicate test execution (tooling).** `packages/game` and `packages/content` tsconfigs lacked the
   `src/**/*.test.ts` exclude that `apps/server` and `packages/contracts` have, so `tsc --build` emitted
   `dist/*.test.js` copies that Vitest ran a second time. That is why M1-10 reported "24 files / 208 tests".
   The real count is now reported: 17 files / 137 tests, including 3 new tests.
6. **`scripts/simulate.mjs` silently ignored its documented `--seed 1` form (tooling).** It now accepts both
   `--key value` and `--key=value`.
7. `apps/web/index.html`: an empty `data:` favicon removes a `/favicon.ico` 404 on every page load.

**Material decision (recorded here and in README):** the default save moved from
`<cwd>/data/banner-and-bounty.sqlite` (which was `apps/server/data/` under `npm run dev`) to
`<repo>/data/banner-and-bounty.sqlite` for both `npm run dev` and `npm start`. This matches tech-stack.md's
`data/` layout and gives one save location. Old dev saves are not deleted; README explains how to move one.
`DB_PATH` still overrides it.

**Not changed:** no file in `packages/game/src`, `packages/content/src`, `packages/contracts/src` or `design/`.
`git diff 419df6a -- packages` shows only the two tsconfig exclude lines.

   it would mean a contract change to `/dev/session/current`.
3. **Walkthrough coverage gaps:** the equip step hit an empty slot, so the fixed "Now" column was
   exercised only with "Empty", not an occupied slot (that fix was verified by code reading). Boss *loss*
   recovery is not in this run: the first boss attempt at Lv 3 always wins, per tuning.md. M1-08's tests
   and M1-10's live level-1 loss cover it. No contrast-ratio measurement was taken. Screen-reader output
   was not tested.
4. **Accelerated time:** all elapsed-time evidence comes from an injected clock, never real minutes.
   Pacing evidence comes from simulation (check 1), per acceptance.md.
5. **`npm run test:e2e` is still the QA-owned placeholder.** `scripts/walkthrough.mjs` is the engineering
   release-candidate check, not QA's suite. QA can reuse `@playwright/test`, which is now installed.
6. **Only tested on Windows 11 with Edge.** PowerShell 7 was not tested.
7. **Boss readiness coincides with level 3.** This is an owner-accepted design decision per tuning.md, not
   an engineering defect. The `design/decisions.md` logging gap noted there is unchanged.
