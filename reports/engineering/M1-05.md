### 2. `npm run dev` starts UI/API on 5174/3100 with configurable ports; health and browser shell work without cloud services — PASS

- `npm run dev` (via `node scripts/dev.mjs`) started both processes: `[server] listening on http://127.0.0.1:3100` and Vite `ready ... Local: http://localhost:5174/`.
- `GET http://127.0.0.1:3100/health` → `{"ok":true,"data":{"status":"ok","schemaVersion":0}}`.
- `GET http://localhost:5174/` → `200`. **Limitation found and fixed:** the same request to `http://127.0.0.1:5174/` initially failed with `ECONNREFUSED` — Vite's default `server.host` resolves `"localhost"` in a way that did not bind the literal IPv4 loopback on this Windows box. Fixed by setting `server.host: "127.0.0.1"` explicitly in `apps/web/vite.config.ts`; re-ran `npm run dev` after the fix and confirmed `GET http://127.0.0.1:5174/` → `200`.
- No cloud account, Docker, or external service was needed for either process.

### 3. Port conflict and shutdown behavior are exercised; no hidden external service or global package-manager requirement — PASS, with a documented caveat

- **Port conflict:** held port 3100 with a raw `net.Server`, then ran `node scripts/dev.mjs` as a child — it printed `[dev] port 3100 (API) is already in use on 127.0.0.1. Set API_PORT to a free port and retry.` and exited with code 1, without touching port 5174. Confirms the pre-flight check and clear, actionable message.
- **Clean shutdown (direct signal):** ran `node scripts/dev.mjs` as the harness's direct background process, confirmed both ports listening (`Get-NetTCPConnection` → PIDs on 3100 and 5174), then stopped that task. Re-checked: `Get-NetTCPConnection -LocalPort 3100,5174` → no listeners. Clean teardown confirmed when the launcher process itself receives the termination.
- **Caveat found:** an earlier run where the harness's background task wrapped `npm run dev` (an extra `cmd.exe`/npm layer deeper than the direct-`node scripts/dev.mjs` case above) left two orphaned `node.exe` processes still bound to 3100/5174 after the task was stopped — the external stop did not reach the grandchildren. This is a property of killing a `.cmd`-wrapped tree from *outside* the Node process (no signal delivery through that layer), not a bug in `dev.mjs`'s own signal handling: `dev.mjs` close its own children correctly whenever it receives a signal directly (verified above), and a real terminal's Ctrl+C delivers the console-control event to the whole process group, which is the normal supported path. Documented this in the README as a known Windows limitation of out-of-band process killers; recommends using an interactive terminal's Ctrl+C or targeting `node scripts/dev.mjs`'s own PID. Manually cleaned up the two orphaned processes via `Stop-Process` afterward (not part of the shipped tooling — a one-off manual cleanup for this verification run).
- No global package manager beyond npm; no Docker/cloud dependency anywhere in the dev path.

## Unresolved issues / limitations for the next task

1. `node:sqlite` works on Node 22.14.0 but is still flagged experimental by Node itself (`ExperimentalWarning`). M1-07 (session/storage) should re-confirm this on whatever Node version is pinned when it starts, and decide whether to suppress/accept the warning in server logs.
2. Killing a `npm run dev`-wrapped process tree from *outside* Node on Windows (e.g., a task manager that doesn't forward signals through the `.cmd` layer) can orphan the API/UI child processes holding the ports. `dev.mjs`'s own signal handling (direct Ctrl+C or killing its own PID) is confirmed clean; this is a documented caveat, not a code defect, but M1-07+ should be aware when scripting any automated process supervision.
3. `packages/contracts`/`game`/`content` are intentionally empty placeholders (a version marker + one test) — no DTO/Zod schemas, no simulation functions, no content tables yet. That is explicitly out of scope for M1-05 per the task brief; M1-02/M1-04/M1-07 implement the real surfaces against this scaffold.
4. `npm run test:e2e` and `npm run simulate` are reserved script names only; no `tests/e2e/` or simulation engine exists yet (both out of this task's write scope — `tests/e2e/` belongs to QA, `simulate` is M1-12).
